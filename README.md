# ハナタバ — お祝い花取りまとめWebアプリ

有志で贈るお祝い花（開店祝い・就任祝い・発表会など）の取りまとめを、幹事・参加者・花屋の三者でスムーズに進めるためのWebアプリです。

- **幹事** — 企画を作成し、共有URLを配って参加を集め、集計・CSV出力・受付終了までを管理
- **参加者** — ログイン不要。共有URLから名前・金額・メッセージを登録
- **花屋** — 注文内容をまとめて確認し、制作ステータスの更新と完成写真のアップロード
- **完成報告** — 完成写真と花屋のコメントを、参加者全員が専用URLから閲覧

## 技術構成

| 項目 | 採用技術 |
| --- | --- |
| フレームワーク | Next.js 16（App Router） |
| 言語 | TypeScript |
| バックエンド | Supabase（Postgres / Auth / Storage） |
| スタイリング | Tailwind CSS |
| UI | 日本語・スマートフォン最適化 |

## セットアップ

### 1. 依存関係のインストール

```bash
npm install
```

### 2. Supabase プロジェクトの準備

1. [Supabase](https://supabase.com/) でプロジェクトを作成します。
2. SQL Editor を開き、`supabase/schema.sql` の内容をそのまま実行します。
   テーブル・RLSポリシー・Storageバケット（`flower-photos`）がまとめて作成されます。
3. Authentication → Providers で「Email」を有効にします。
   動作確認をすぐに行いたい場合は、Email Confirmation を一時的に無効にすると登録後すぐログインできます。

### 3. 環境変数

`.env.example` を `.env.local` にコピーして値を設定します。

```bash
cp .env.example .env.local
```

| 変数 | 説明 |
| --- | --- |
| `NEXT_PUBLIC_SUPABASE_URL` | Supabase のプロジェクトURL |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | anon（公開）キー |
| `SUPABASE_SERVICE_ROLE_KEY` | service role キー。**サーバー専用**。参加者向けの共有URLページでのみ使用します |
| `NEXT_PUBLIC_APP_URL` | 共有URL生成に使う本番URL（未設定の場合はリクエストのホスト名を使用） |

> `SUPABASE_SERVICE_ROLE_KEY` はRLSをバイパスします。クライアントへ渡らないよう、`NEXT_PUBLIC_` を付けないでください。

### 4. 開発サーバーの起動

```bash
npm run dev
```

http://localhost:3000 が開きます。

## 使い方

1. `/signup` から「幹事」または「花屋」を選んでアカウントを作成します。
2. 幹事でログインし、`/organizer/new` から企画を作成します。作成後、共有URL（`/j/<token>`）が発行されます。
3. 参加者に共有URLを配ります。参加者はログイン不要で登録できます。
4. 幹事は `/organizer/<id>` で参加人数・合計金額・目標までの残額・参加者一覧・メッセージ一覧を確認し、CSV出力や受付終了を行えます。
5. 花屋は `/florist` で全企画の注文内容を確認し、制作ステータスの更新・完成写真のアップロード・コメントの記入を行います。
6. 制作ステータスを「完成」以降にすると、完成報告ページ（`/r/<token>`）が参加者に案内されます。

## 画面構成

| パス | 認証 | 内容 |
| --- | --- | --- |
| `/` | 不要 | サービス紹介 |
| `/signup` `/login` | 不要 | 幹事・花屋のアカウント登録／ログイン |
| `/organizer` | 幹事 | 自分の企画一覧 |
| `/organizer/new` | 幹事 | 企画作成フォーム |
| `/organizer/[id]` | 幹事 | 集計・参加者一覧・メッセージ・CSV出力・受付終了 |
| `/organizer/[id]/csv` | 幹事 | 参加者一覧のCSVダウンロード |
| `/j/[token]` | **不要** | 参加者向け登録ページ |
| `/florist` | 花屋 | 全企画の注文一覧 |
| `/florist/[id]` | 花屋 | 注文詳細・制作ステータス・完成写真・コメント |
| `/r/[token]` | **不要** | 完成報告ページ |

## データモデル

- `profiles` — ユーザーの表示名とロール（`organizer` / `florist`）。`auth.users` の作成時にトリガーで自動生成
- `projects` — 企画。参加用の `share_token` と完成報告用の `report_token` を持つ
- `participants` — 参加者。氏名・金額・メッセージ・札名掲載可否・匿名フラグ
- `project_photos` — 完成写真（Storage の `flower-photos` バケットと対応）

## 権限設計

- 幹事は自分が作成した企画とその参加者のみ参照・更新できます。
- 花屋アカウントは全企画を参照できます（1つの花屋が全注文を受ける前提の設計です）。
  複数店舗で運用する場合は、`projects` に店舗IDを持たせてポリシーを絞り込んでください。
- 花屋が `projects` で変更できるのは制作ステータス・コメント・完成写真のみです。
  企画名や金額、共有トークンなどの書き換えはトリガー（`guard_project_columns`）で拒否されます。
- 参加者ページと完成報告ページは未認証で閲覧するため、サーバー側で service role を使い、
  URLトークンに一致する企画のみを読み書きします。トークンは16進24文字（96bit）のランダム値です。

## 制限事項

- **オンライン決済機能はありません。** 集金は幹事が別途行う前提です。
- 参加者ページでは個々の参加金額を表示せず、合計と参加者名のみを公開します。
- 参加者の登録はトークンを知っていれば誰でも行えます。重複登録の抑止は行っていないため、
  必要に応じて幹事が管理画面から削除してください。
